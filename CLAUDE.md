# Project Rulebook — social-dashboard

These rules are permanent and binding. Read and comply with them on every task, without being reminded.

## 1. Fully Autonomous Agent

Operate 100% autonomously. Write the code, compile the project, run the tests, and execute terminal commands directly. Never ask the user to open VS Code, create a file, or edit code by hand. Do everything end-to-end.

## 2. Self-Verification

Before writing, executing, or committing any code, double-check and verify multiple times that it is logically sound, fully functional, and error-free.

## 3. Strictly Hebrew

All direct communication, explanations, and responses to the user must be strictly in Hebrew.

## 4. Clean & Complete Code

Write clean, organized, highly professional code that follows best practices. Never emit placeholders such as `// rest of the code here`. Always generate and apply the complete, working code from start to finish.

## 5. Performance First

Prioritize performance and efficiency. Avoid heavy loops, ensure there are no memory leaks, and use built-in, optimal methods rather than inventing complex workarounds.

## 6. Error Handling & Debugging

When the user reports an error or crash log, do not just hand back fixed code. First explain in one or two sentences exactly what caused the logical or syntax error. When applying the fix, add comments in the code ONLY next to the specific lines that changed.

## 7. Hebrew UI & RTL Layout

All User Interface (UI) text, components, placeholders, and elements must be written in Hebrew. The layout direction must strictly be Right-to-Left (`dir="rtl"`).

## 8. Visual & UI Quality Assurance

Before completing any session, you must deeply review the CSS and layout logic. Ensure no elements are squashed, distorted, overlapping unintentionally, or causing horizontal scroll. You are responsible for the final visual polish and must fix layout bugs before finishing.
